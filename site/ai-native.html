● AI-native, not AI-bolted-on

AI isn't a chat widget here — it's the ingestion pipeline.

There's no chatbot tacked onto the sidebar. AI reads the receipts, cleans the data, matches the nutrition facts, and is treated as an untrusted input that needs checking — right alongside a few engineering decisions that were just fun to build.

AI native

Where the AI actually does the work

Six places AI is load-bearing infrastructure in this app — not a demo feature.

🔀

Multi-model OCR orchestration

The same OCR pipeline runs against Google Gemini 2.5 Flash in the cloud, or against IBM Granite 3.3 Vision / Qwen2-VL running locally via Ollama or LM Studio — selected with a single environment variable, no code changes.

🔭

Self-healing model discovery

A ModelManager service queries the Gemini API for currently-available models, ranks candidates by preference (flash > pro > latest), and caches the result for a week — so the app keeps working when Google renames or retires a model name out from under it.

🧪

The AI checks its own work

Every OCR pass cross-references extracted line-item prices against the receipt's printed subtotal. If the math doesn't reconcile, the review screen flags it as a likely hallucination before the data is ever saved — the system is built to distrust its own AI output by default.

🔗

AI-driven item resolution, with a non-AI fallback

Gemini matches messy OCR text like ORG BANANA 2LB to canonical products in OpenFoodFacts / USDA FDC for nutrition data. Matching that text to your own purchase history, though, is deliberately not an AI call — it's a local rapidfuzz comparison, because that path runs on every single receipt and needs to be instant and free.

🤖

Agent-friendly APIs, not just human screens

The prediction engine exposes structured, urgency-ranked JSON at /api/predictions/ designed to be called by an agent, not just rendered in a browser. The Restock page even ships a one-click "Send to Agent" button next to each store's shopping list.

🛠️

Built through ensemble AI programming

The codebase itself was developed with a coordinated set of AI models splitting responsibilities — architectural planning, implementation, and OCR-prompt tuning each handed to whichever model was best suited, rather than one model doing everything.

Clever things

Details nobody asked for, that earn their keep

The kind of decisions that only show up if you read the code — or stare at your own grocery data long enough to get curious about it.

🩻

Receipt X-Ray

Five visualizations mined from your own purchase history: a Price Volatility Radar (which items swing in price most), Store DNA Fingerprint (each store's basket signature), The Phantom Items (what you buy on autopilot), Shopping Rhythm (a day-of-week heatmap of when you actually shop), and a Receipt Complexity Score separating quick runs from weekly hauls.

⚡

A zero-AI fast path

Digital PDF receipts (Amazon, iHerb) skip the AI model entirely. A hand-built pdfplumber parser pulls structured data directly from the PDF's text layer — 100% data fidelity, no API cost, and results return in well under a second.

🎨

Tufte-mode, enforced in code

Every chart on the dashboard and trends page pulls from one shared getTufteDefaults() helper — ghost gridlines at ~18% opacity, borderless axes, monospace 9px ticks. Edward Tufte's data-ink-ratio principle isn't a style guide here, it's a function every chart literally calls.

🔁

Bi-directional price math

On the receipt review screen, edit quantity, total line price, or unit price — whichever number you actually have — and the other two recalculate themselves automatically. No "wrong field" to worry about.

🙅

Dismissal memory

Tell the duplicate detector "these are not the same item" once, and an ItemMatchIgnore table makes sure it never suggests that pair again — without ever blocking a future, genuinely different match.

🌡️

Price Weather

A "Thermal Stack" view renders your most-tracked items as color-coded vertical lozenges sized and shaded by price magnitude — a quick visual gut-check for grocery inflation across your own basket.

🗄️

Data archaeology, not data loss

A recovery pass rebuilt 1,288 orphaned records straight from raw JSON logs, and a separate script back-filled unit pricing for 1,300+ items by parsing the weight directly out of item-name text — zero API calls, zero records lost.

🌓

Four themes, one variable swap

Dark, Light, Forest, and Sunset are pure CSS-variable swaps with no per-component theme logic — roughly 330 hardcoded classes were refactored to semantic tokens in a single pass across 13 templates.

📡

Offline-proof by accident-proofing

Every frontend library is vendored locally and the CSP is locked to 'self'. The practical effect: the app keeps working through a Wi-Fi outage, a CDN incident, or a flight with no Wi-Fi at all.
